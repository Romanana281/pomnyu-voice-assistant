# Помню

Голосовой ассистент для задач, напоминаний и встреч. Говорите или пишите как обычно: «напомни завтра в 10 позвонить Ивану», «что у меня на неделе?», «найди задачу про договор». Помню разберёт фразу, сохранит запись, ответит голосом и задаст уточняющий вопрос, если чего-то не хватает.

## Возможности

| | Примеры |
|---|---|
| **Задачи и напоминания** | «Напомни мне завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт», «Поставь задачу купить билеты до конца недели», «Через два часа напомни выпить воды» |
| **Встречи** | «Добавь встречу с командой завтра в 15:00», «В четверг в 11 у меня встреча с дизайнером» |
| **Планы на период** | «Что у меня сегодня?», «Какие планы на сегодня?», «Покажи мои встречи на сегодня», «Что запланировано на эту неделю?», «Что у меня в выходные?» |
| **Поиск по смыслу** | «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?», «Я когда-то ставил задачу по договору, найди её» — найдёт «Подписать контракт с подрядчиком» |
| **Уточняющий диалог** | «Поставь встречу с Иваном завтра» → «На какое время?» + свободные слоты → «давай в три» |
| **Контекст** | «А перенеси её на завтра», «удали вторую», «сделано» |
| **Несколько просьб сразу** | «Что у меня сегодня и назначь звонок с мамой на 19:00» |
| **Изменение и удаление** | «Сдвинь встречу с Иваном на 16:30», «Отмени встречу с дизайнером» — с подтверждением и кнопкой «Вернуть» |
| **Выполнение** | «Отметь задачу про отчёт выполненной» или галочка в планах |
| **Конфликты встреч** | Ассистент показывает пересечение на таймлайне и предлагает ближайшее свободное время |
| **Повторы** | «Каждый понедельник в 10 планёрка», «По будням в 9 напоминай проверить почту» |
| **Календари** | Экспорт: подписка на ICS-ленту в Google, Apple, Outlook. Импорт: файл `.ics` или ссылка, синхронизация каждые 30 минут |
| **Устройства** | Без регистрации; телефон подключается по QR-коду, задачи и чаты общие и обновляются сами |
| **Чаты** | Отдельные беседы в боковой панели, у каждой свой контекст |

Интерфейс адаптирован под телефон, ставится как приложение (PWA), поддерживает светлую и тёмную темы и работает и голосом, и текстом.

## Быстрый старт

Понадобится Docker и ключ авторизации GigaChat: [developers.sber.ru](https://developers.sber.ru/studio) → проект GigaChat API → «Ключ авторизации». Для личного использования хватает бесплатного тарифа.

```bash
cp .env.example .env.local      # вставьте ключ в GigaChat__AuthKey
docker compose up -d --build
```

Откройте http://localhost:8080. Браузер даёт доступ к микрофону только на `localhost` и по HTTPS. Распознавание речи работает в Chrome, Edge и Safari, в Firefox можно писать текстом.

<details>
<summary>Запуск без Docker</summary>

```bash
export GigaChat__AuthKey="<ключ авторизации>"
dotnet run --project src/Assistant.Web
```

Нужен .NET 10 SDK. На macOS системный TLS-стек .NET отклоняет сертификат серверов Сбера, поэтому на Mac используйте Docker. На Linux и Windows всё работает напрямую.
</details>

### Настройки

| Переменная | По умолчанию | |
|---|---|---|
| `GigaChat__AuthKey` | — | Ключ авторизации GigaChat, обязателен |
| `GigaChat__Scope` | `GIGACHAT_API_PERS` | `GIGACHAT_API_B2B` / `GIGACHAT_API_CORP` для юрлиц |
| `GigaChat__ChatModel` | `GigaChat-2-Pro` | Модель разбора запросов |
| `GigaChat__FallbackChatModel` | `GigaChat-2` | Используется, если основная недоступна по тарифу |
| `GigaChat__EmbeddingModel` | `Embeddings` | Эмбеддинги для поиска по смыслу (если есть в тарифе) |
| `DataDirectory` | `data`, в Docker — `/data` | База SQLite и ключи подписи cookie |

## Архитектура

```
Браузер (PWA)              голос ⇄ текст в браузере, на сервер уходит только текст
   │  /api/chat · /api/agenda · /api/conversations · /api/items · /calendar/*.ics
   ▼
Assistant.Web              HTTP, cookie-сессия, контракт ошибок, ICS, фоновая синхронизация календарей
   ▼
Assistant.Application      понимание → команда → обработчик → ответ; история чатов; импорт календарей
   │  порты: ILlmClient, IEmbeddingProvider, IScheduleRepository, IChatHistoryRepository, …
   ▼
Assistant.Domain           ScheduleItem, Recurrence, Conversation, ChatMessage, AppUser — инварианты
   ▲
Assistant.Infrastructure   GigaChat (OAuth, очередь, ретраи), EF Core + SQLite, безопасная загрузка календарей
```

Зависимости направлены внутрь: домен ни от чего не зависит, Application работает только с интерфейсами, а конкретные GigaChat и SQLite подключаются в Infrastructure. Чтобы перейти на другую модель, достаточно новой реализации `ILlmClient`.

### Как обрабатывается реплика

1. **Речь → текст** в браузере: `SpeechRecognition`, `ru-RU`, запись заканчивается после паузы.
2. **Несколько просьб.** Если в реплике их несколько, модель сначала делит её на части, и каждая часть выполняется отдельно.
3. **Понимание.** GigaChat выбирает функцию из закрытого набора (`create_task`, `create_meeting`, `list_items`, `search_items`, `update_item`, …).
   - Относительные даты модель возвращает ключевыми словами (`tomorrow`, `fri`, `next_wed`, `end_of_week`, `in_minutes`), а сами даты считает сервер: в календарной арифметике LLM ошибаются.
   - `MentionGuard` убирает дату и время, которых не было в реплике.
   - `IntentOverrides` страхует однозначные намерения («удали…», «напомни…»).
4. **Проверка.** Ответ модели считается внешними данными: проверяются формат, диапазоны и перечисления. Некорректный ответ превращается в вежливое «не понял», а не в ошибку.
5. **Выполнение.** `CommandDispatcher` передаёт команду обработчику её сценария. Если данных не хватает, обработчик задаёт уточняющий вопрос.
6. **Ответ:** текст с правильными падежами для экрана и озвучки плюс карточка (сохранено, было → стало, черновик, конфликт, план, результаты поиска).

### Диалог

Состояние диалога своё у каждого чата: последняя обсуждавшаяся запись, последний показанный список, черновик, ожидающий уточнения, и подтверждение. Необратимые действия подтверждаются детерминированно: короткие «да» и «нет» распознаются без модели, а отложенная команда хранится на сервере, поэтому модель не может удалить запись сама.

### Поиск

- **Синонимы.** Модель добавляет к запросу близкие слова: «договор» → контракт, соглашение, подписать.
- **Корни слов.** Совпадение с учётом окончаний: «Иваном» ≈ «Ивану», «звонок» ≈ «позвонить».
- **Эмбеддинги** GigaChat, если они есть в тарифе. Если модель эмбеддингов отвечает «недоступно по тарифу», приложение на час перестаёт к ней обращаться.

### Данные и синхронизация

- **Записи.** Время хранится по часам пользователя (`DateOnly` + `TimeOnly`), повторы — в виде RRULE, удаление мягкое.
- **Чаты.** История хранится на сервере, поэтому видна на всех устройствах пользователя.
- **Работа клиента.** Клиент показывает данные мгновенно из кэша и сверяется с сервером в фоне: раз в 15 секунд и при возврате на вкладку. В интерфейсе меняются только изменившиеся элементы, поэтому обновления не мешают пользователю.

### Безопасность и надёжность

- **Изоляция данных.** Каждый запрос к базе ограничен пользователем. Сессия хранится в подписанной cookie; ссылка для второго устройства одноразовая и живёт 10 минут.
- **Защита от SSRF при импорте по ссылке:**
  - разрешены только http и https, без логина в URL;
  - соединение идёт только с публичными IP, проверка выполняется на уровне сокета, в том числе после редиректов;
  - лимиты: 5 МБ и 20 секунд.
- **Вызовы GigaChat** идут через очередь (бесплатный тариф допускает один поток), с ретраями и circuit breaker. Если основная модель недоступна по тарифу, используется резервная.
- **Ошибки API** приходят в едином формате: 400 с указанием поля, 404, 409, 503 при недоступной модели, 500 с `requestId` в логе.

## Принятые решения

- **GigaChat** хорошо понимает русский и даёт function calling и эмбеддинги по одному ключу, у него есть бесплатный тариф.
- **Распознавание речи в браузере** бесплатно, работает без ключей и с низкой задержкой; сервер не зависит от способа ввода.
- **Function calling вместо свободного JSON:** модель выбирает из фиксированного набора действий, аргументы проверяются по схеме.
- **Даты считает код, а не модель:** надёжнее для «в пятницу» и «до конца недели».
- **Без регистрации:** проверяющему не нужно заводить аккаунт, данные всё равно изолированы.
- **ICS вместо Google Calendar API:** работает с любым календарём и не требует OAuth.
- **SQLite:** один файл на volume, отдельный сервер базы не нужен.
